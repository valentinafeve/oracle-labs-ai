Para crear el api key, podemos usar el siguiente paso a paso [Creación de un api key paso a paso](../utils/Creación%20de%20credenciales.md)

### Paso 4.2: Creación y configuración del usuario

Cuando la base de datos esté en estado available podemos acceder a esta y ejecutar comandos SQL

![image.png](AI%20Private%20Agent%20Factory/image%205.png)

Dentro del SQL, ejecutaremos el siguiente script, el cuál creará el usuario y asignará los permisos necesasrios

```sql
CREATE USER <DB_USER> IDENTIFIED BY <DB_PASSWORD> DEFAULT TABLESPACE USERS QUOTA unlimited ON USERS;
GRANT CONNECT, RESOURCE, CREATE TABLE, CREATE SYNONYM, CREATE DATABASE LINK, CREATE ANY INDEX, INSERT ANY TABLE, CREATE SEQUENCE, CREATE TRIGGER, CREATE USER, DROP USER TO <DB_USER>;
GRANT CREATE SESSION TO <DB_USER> WITH ADMIN OPTION;
GRANT READ, WRITE ON DIRECTORY DATA_PUMP_DIR TO <DB_USER>;
GRANT SELECT ON SYS.V_$PARAMETER TO <DB_USER>;
```

Si quieres usar directamente el usuario y contraseña sugeridos para el workshop, puedes ejecutar este comando:

```sql
CREATE USER LOANAPP IDENTIFIED BY L1o2a3n4a5p6p7$ DEFAULT TABLESPACE USERS QUOTA unlimited ON USERS;
GRANT CONNECT, RESOURCE, CREATE TABLE, CREATE SYNONYM, CREATE DATABASE LINK, CREATE ANY INDEX, INSERT ANY TABLE, CREATE SEQUENCE, CREATE TRIGGER, CREATE USER, DROP USER TO LOANAPP;
GRANT CREATE SESSION TO LOANAPP WITH ADMIN OPTION;
GRANT READ, WRITE ON DIRECTORY DATA_PUMP_DIR TO LOANAPP;
GRANT SELECT ON SYS.V_$PARAMETER TO LOANAPP;
```

## Notas de investigación

### Validación para ambientes `Trial` / `Always Free`

Los valores que aparecen después de elegir `VM.Standard.E5.Flex`, por ejemplo:

- `Agent Factory OCPUs (Flex only): 16`
- `Agent Factory Memory (GB) (Flex only): 128`

no deben asumirse como válidos en una tenancy Trial solo porque la consola los muestre como opciones del shape.

### Lo que se confirmó en la documentación oficial

1. `VM.Standard.E5.Flex` no es un recurso Always Free. En Always Free, los recursos de cómputo relevantes son `VM.Standard.E2.1.Micro` y `VM.Standard.A1.Flex`, esta última con hasta `4 OCPUs` y `24 GB` en total, en la región home.
2. Un tenant `Free Trial` sí puede consumir servicios elegibles usando los créditos promocionales, pero eso sigue sujeto a los service limits de la tenancy.
3. Para la familia `VM.Standard.E5` en modalidad `Pay As You Go or Trial`, la documentación de OCI publica por defecto:
   - `standard-e5-core-count`: `6` OCPUs por availability domain
   - `standard-e5-memory-count`: `72 GB` por availability domain
4. Por lo tanto, una VM de `16 OCPUs / 128 GB` en `VM.Standard.E5.Flex` normalmente excede los límites por defecto de una tenancy Trial. No es imposible en términos absolutos, pero sí requiere que tu tenancy tenga ese cupo efectivo disponible.
5. La documentación general de Agent Factory no respalda `128 GB` como requisito mínimo. En la instalación desde OCI Marketplace, Oracle documenta para shapes Flex un mínimo de `8 CPU cores`, `16 GB RAM` y `120 GB` de boot volume.
6. En este workshop se observó además que la UI del stack puede imponer una validación más estricta en memoria. Si el formulario muestra `Memory in GB for Flex shape. Specify at least 64`, entonces para ese stack concreto se debe usar al menos `64 GB`, aunque la documentación general del producto mencione un mínimo menor.
7. En la guía de prerequisitos también aparece un requerimiento de `100 GB`, pero corresponde al tablespace del usuario de base de datos usado por Knowledge Assistant, no a la memoria RAM de la VM de Agent Factory.

### Recomendación práctica para este workshop

Si el límite aparece como `Dynamic` y no tienes un valor fijo visible, la recomendación práctica para este workshop es:

- `Agent Factory OCPUs (Flex only)`: `8`
- `Agent Factory Memory (GB) (Flex only)`: `64`

Motivo:

- `8 OCPUs` es el mínimo que exige el stack de Marketplace para esta instalación.
- si la UI del stack muestra `Specify at least 64`, ese valor de memoria manda para este formulario específico.
- `64 GB` sigue siendo más prudente que dejar `128 GB`, y reduce la probabilidad de pedir más memoria de la necesaria en una tenancy Trial.

### Cómo verificarlo en tu tenancy

En la consola OCI ve a:

`Governance & Administration` -> `Limits, Quotas and Usage` -> `Compute`

Revisa específicamente estos límites:

- `standard-e5-core-count`
- `standard-e5-memory-count`

Si tu tenancy muestra esos valores por debajo de `16` y `128`, entonces esa configuración alta puede fallar por límite/capacidad. Si el límite aparece como `Dynamic`, la forma práctica de validar es intentar con el mínimo que exige el stack.
